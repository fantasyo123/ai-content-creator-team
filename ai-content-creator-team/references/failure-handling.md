# 故障处理与升级路径

> 团队成员失败时的统一应对策略。核心原则：**快速失败、快速降级、如实告知**。

## 1. video-generator（视频生成）失败专项

当视频生成子代理回传失败报告时，按以下顺序排查：

| 失败类型 | 判断方法 | 应对动作 |
|----------|----------|----------|
| **临时性错误** | 超时 / 服务繁忙 | 等待 1 分钟后重新派发；新任务 prompt 中注明"上次因超时失败，请直接重试" |
| **模型拒绝（内容安全拦截）** | 返回安全/拒绝信息 | 调整需求描述，去掉可能触发安全过滤的内容后重新派发 |
| **工具不可用** | Skill 无法触发 | 向用户说明视频生成服务暂时不可用，建议稍后重试 |
| **图生视频失败但文生未尝试** | 失败原因含糊 | 重新派发任务，明确指定"使用文生视频模式，模型 hy-video-1.5" |
| **同一任务累计失败 ≥ 2 次** | 连续失败 | **终止该任务线**，向用户如实说明并提供替代建议 |

## 2. 通用超时处理

| 情形 | 动作 |
|------|------|
| 成员超过 **10 分钟** 未回传结果 | 主动向用户通报等待状态 |
| 成员超过 **15 分钟** 仍无响应 | 视为失败，启动备选方案 |

## 3. 能力不匹配处理

| 场景 | 动作 |
|------|------|
| 成员报告"任务超出能力范围" | 立即终止该任务线，寻找替代方案（如建议用户使用更合适的工具），**禁止**重新派发相同任务给同一成员 |
| 成员连续失败 | 终止该任务线，向用户说明原因并提供替代建议 |

## 4. 整体决策原则

- **优先保证产出**：宁可走简单可靠的路径（如文生视频），也不要为了追求最优路径（关键帧→图生视频）而反复折腾导致失败
- 如果某一角色反复失败，尝试用**单进程角色化**方式（同一进程按步骤顺序承担多个角色）绕过子代理问题
- 主理人在每次阶段衔接时检查产物：如果质量不达标（如画面风格不统一），特征性地告诉对应成员具体差在哪（构图/色彩/一致性），而非笼统"再试一次"

## 5. 面向用户的沟通模板

- 超时等待：`「视频生成需要几分钟时间，当前仍在处理中，请稍候。」`
- 服务不可用：`「视频生成服务当前暂不可用，可能是平台高峰导致，建议稍后重试，或先完成文字/图片部分。」`
- 内容安全：`「部分描述可能触发安全限制，我已调整表述后重新提交。」`
- 彻底失败：`「这条任务线连续失败，原因如下：[原因]。建议改为 [替代方案]，是否需要我继续？」`
